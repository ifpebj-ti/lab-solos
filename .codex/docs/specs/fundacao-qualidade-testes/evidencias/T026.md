## Cobertura entregue

Os quatro casos usam Chromium para autenticação e chamadas `fetch` reais do
navegador, API HTTP real, PostgreSQL descartável e consultas autorizadas para
confirmar o estado persistido. Cada caso prepara um identificador de cenário
distinto por meio do helper de T023, sem contas globais nem dados de outra
tarefa. As verificações posteriores usam novo contexto de navegador.

| Critério | Evidência automatizada |
|---|---|
| CT-006 — solicitação | Mentorado autenticado cria `POST /api/Emprestimos` e recebe `201`; o empréstimo fica `Pendente`, vinculado ao sujeito da sessão e aparece na listagem por usuário. Criação anônima e administrativa recebem `401`. |
| CT-007 — aprovação | Administrador consulta a lista, aprova via `PATCH` real com `204`, e um novo contexto confirma `Aprovado`, aprovador vinculado e estoque de `100` para `98`. A segunda aprovação recebe `400` e o estoque permanece `98`. |
| CT-007 — estoque insuficiente | Solicitação acima do estoque recebe `400` na aprovação; novo contexto confirma empréstimo `Pendente` e estoque `100`. A repetição continua em `400`, sem alteração parcial. |
| CT-008 — rejeição | Administrador rejeita via `PATCH` real com `204`; novo contexto confirma `Rejeitado`, aprovador vinculado e estoque `100`. A segunda rejeição recebe `400`, sem alteração. |
| Autorização e IDs ausentes | Mentorado tentando decidir recebe `403`; aprovar/reprovar ID inexistente recebe `404`; nenhum desses caminhos cria ou modifica empréstimo/produto. |

Não foram usados `route.fulfill`, `page.route` para endpoints de domínio,
exclusão global de Mailpit, contas globais ou dados compartilhados de outra
tarefa. Nenhum valor de senha, token JWT ou segredo foi impresso na saída ou
nesta evidência.

## RED / GREEN / REFACTOR

- **RED de descoberta histórico:** na execução anterior, antes da correção da
  configuração compartilhada pelo pai, o comando oficial retornou `No tests
  found` para `loans.spec.ts`. A retomada foi iniciada somente depois de a
  entrada de T026 ser incluída no projeto `real`; a descoberta atual confirmou
  quatro testes.
- **RED funcional:** na primeira execução do arquivo por configuração
  efêmera, três casos passaram e o caso de perfil proibido falhou porque o
  teste esperava `401`, enquanto o middleware real retornou `403` para a
  política administrativa. A expectativa foi corrigida para o contrato HTTP
  observado.
- **GREEN:** o comando oficial em stack limpa executou os quatro casos reais e
  terminou com `4 passed (1.5m)`.
- **REFACTOR:** as asserções repetidas de estoque e status permanecem extraídas
  para `expectProductQuantity` e `expectLoanStatus`; a suíte final passou pelo
  comando oficial após essa organização.

backend `28281` e frontend `24276`, com `E2E_SEED_SCENARIO=t026`. O Compose foi
