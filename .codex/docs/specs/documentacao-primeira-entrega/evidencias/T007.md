## GREEN

O validador passou a:

- localizar uma seção declarada no manifesto e extrair seu bloco `.env` sem atravessar a próxima seção do mesmo nível;
- conferir variáveis interpoladas, incluindo operadores de valor padrão e `LABON_IMAGE_VERSION` obrigatório;
- escrever cada exemplo somente em arquivo temporário e removê-lo com `TemporaryDirectory`;
- executar `docker compose ... config --quiet` por lista de argumentos, com `shell=False`;
- remover variáveis de Compose/Docker herdadas do processo para impedir sobrescrita dos exemplos;
- classificar Docker ausente/daemon indisponível como infraestrutura (código 2) e configuração inválida como contrato (código 1);
- não imprimir stdout/stderr do subprocesso.

Comandos verdes:

```text
python -m unittest test_delivery_docs.ComposeValidatorContractTests -v
python -m unittest discover -s .github/scripts/tests -p "test_delivery_docs.py" -v
```

Resultados: 8/8 testes Compose e 19/19 testes documentais passaram. A cobertura inclui ambiente herdado, seção selecionada, remoção do temporário, lista sem shell, stderr sanitizado, Docker ausente, dois Compose reais (desenvolvimento e produção) via CLI e produção sem `LABON_IMAGE_VERSION`.

O teste de integração usou checkout temporário, manifesto sintético e os arquivos reais `docker-compose-dev.yml`, `docker-compose-prod.yml`, `Caddyfile` e o guia da Wiki. O Docker disponível foi confirmado por:

```text
docker info --format '{{.ServerVersion}}/{{.OSType}}'  -> 29.8.0/linux
docker compose version                         -> v5.5.1
```
